# RFC 2119 severity normalization

Use RFC 2119 terms to express obligation and permission in behavior-defining prose.

Primary source: https://datatracker.ietf.org/doc/html/rfc2119

## When to apply this

Apply this normalization when editing or auditing skill prose, agent instructions, workflow guidance, guardrails, or other behavior-bearing text that uses informal severity labels such as `critical`, `important`, `mandatory`, or `optional`.

Do not apply it mechanically to:

- quoted source text the user wants preserved
- exact tokens, labels, or examples that define external interfaces
- logs, errors, code, commands, file paths, or identifiers

## Preferred RFC 2119 terms

Use the RFC terms that match the actual obligation level:

- **MUST** / **REQUIRED** — absolute requirement
- **MUST NOT** — absolute prohibition
- **SHOULD** / **RECOMMENDED** — strong recommendation with possible valid exceptions
- **SHOULD NOT** — strong recommendation against, with possible valid exceptions
- **MAY** / **OPTIONAL** — permitted, discretionary behavior

## Normalization guidance

Translate rhetorical severity into obligation language.

Examples:

- `critical` requirement → `MUST` or `REQUIRED`
- `important` guidance → `SHOULD` or `RECOMMENDED`
- `optional` step → `MAY` or `OPTIONAL`
- `never` prohibition → usually `MUST NOT` when the rule is meant as a formal hard stop

Choose the term that matches behavior. Do not strengthen or weaken the source rule by accident.

## Editing rule

If a user asks for behavior-preserving cleanup and the source uses severity labels like `CRITICAL` or `IMPORTANT`, rewrite them into RFC 2119 terms unless the wording is an exact token or quoted text that must stay unchanged.

Prefer obligation language over theatrical severity labels. `CRITICAL` tells the reader how loudly to feel the rule. `MUST` tells the reader what level of compliance the rule requires.

## Audit rule

When auditing, flag informal severity words if they obscure whether the text is a requirement, recommendation, permission, or prohibition. Suggest the matching RFC 2119 term when that clarification would reduce ambiguity.
